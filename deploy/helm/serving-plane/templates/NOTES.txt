1. Reach the UI

   http{{ if .Values.ingress.tls.enabled }}s{{ end }}://{{ .Values.ingress.host }}/
{{- else }}
   Ingress is disabled. Port-forward instead:
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "serving-plane.componentFullname" (dict "root" . "component" "ui") }} 3001:{{ .Values.service.ui.port }}
   then open http://localhost:3001/

2. Admin console login
   email    : {{ include "serving-plane.adminEmail" . }}
{{- if include "serving-plane.adminPassword" . }}
   password : the value you set in admin.password
{{- else }}
   password : generated by the chart (kept across upgrades). Read it with:
     kubectl -n {{ .Release.Namespace }} get secret {{ include "serving-plane.adminSecretName" . }} -o jsonpath='{.data.ADMIN_PASSWORD}' | base64 -d; echo
{{- end }}

3. Current configuration
   PII detection      : {{ .Values.servingPlane.policy.piiDetection }}
   compression (CCR)   : {{ .Values.servingPlane.contextOptimization.enabled }} ({{ .Values.servingPlane.contextOptimization.ccr.enabled }})
   Langfuse host       : {{ .Values.langfuse.host }}
{{- if eq .Values.servingPlane.policy.piiDetection "presidio" }}
   NOTE: presidio needs an api image built with EXTRAS=observability,postgres,presidio.
{{- end }}

   Toggle PII / compression without rebuilding images:
   helm upgrade {{ .Release.Name }} <chart> --reset-then-reuse-values \
     --set servingPlane.policy.piiDetection=regex \
     --set servingPlane.contextOptimization.enabled=true \
     --set servingPlane.contextOptimization.ccr.enabled=true

   These are rendered into the {{ include "serving-plane.fullname" . }}-serving-config
   ConfigMap (overlaying /app/config/serving.yaml) and, for the switches the
   app also reads from env (PII detection, port, context optimization on/off),
   set directly on the api container too — the Deployment's pod-template
   annotation forces a rollout on any config change.

   On-prem models are onboarded at runtime (Infrastructure -> Onboard in the
   console, or POST /admin/infra/models); this chart deploys no inference.

4. Where Langfuse is
   This chart does NOT deploy Langfuse — point servingPlane at wherever
   Langfuse already runs (self-hosted or managed) via `langfuse.host`, and
   reference its API keys through an EXISTING Kubernetes Secret:
     --set langfuse.existingSecret=<secret-name>
   (Secret must have keys `langfuse-public-key` / `langfuse-secret-key`.)
   Do not put keys in values.yaml or on the command line in a shared cluster;
   `langfuse.createSecret.enabled` exists only for a disposable dev install.

{{- if .Values.servingPlane.server.streamDecisions }}

5. WARNING — decision stream (SSE) is enabled
   servingPlane.server.streamDecisions=true exposes a live per-request
   decision stream (tenant, entity, cost metadata) to the UI. This is fine for
   a single-tenant demo. In any multi-tenant or customer-facing deployment,
   this endpoint MUST sit behind authentication and be tenant-scoped at the
   ingress/gateway layer — this chart does not implement that auth, it only
   exposes the switch. Do not expose it unauthenticated outside a demo.
{{- end }}

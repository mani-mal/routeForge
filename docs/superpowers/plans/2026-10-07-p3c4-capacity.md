# P3c-4 Capacity Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the offline policy simulator say how loaded each endpoint would be under a policy change — replayed demand per time bucket against limits the operator states — so "all healthcare traffic on-prem" shows "on-prem demand reaches 230% of stated capacity" next to its cost, and says plainly what that figure is not.

**Architecture:** One new offline module, `app/eval/capacity.py`. Each row is still replayed once. Capacity is an operator-stated assumption, like `workload.token_scale`: a `--capacity` file states limits for the deployment as it is (both arms), and a proposal's new `capacity` key states what a change would make them (proposed arm). Demand is computed after replay from the `RowResult`s the simulator already holds: per arm, per endpoint, per epoch-aligned time bucket, by estimated arrival time. `ArmResult` gains the two token counts the arm priced the call at. `app/eval/scenarios.py` and `scripts/policy_simulate.py` each gain an opt-in path that adds one key to their output. Nothing is added to the applied snapshot document or the `assumptions` block, which is what keeps default output byte-identical.

**Tech Stack:** Python 3.12 standard library only, pytest, `uv`. No new dependency. No serving change, no database change, nothing to migrate.

**Spec:** docs/superpowers/specs/2026-10-07-p3c4-capacity-design.md

## Deviations from spec

The spec was amended while this plan was written, so the plan and the spec agree: there is no plan-versus-spec deviation. What follows are the places where the design departs from the brief the spec was written from, or where the brief was silent. The spec lists the same items in its §14. Each follows the code as it is, keeps the brief's intent, and is pinned by a test.

1. **`ts` is not an arrival time.** The brief's caveat said timestamps are request-arrival times at RouteForge. `routing_outcomes.ts` is `default=utcnow` at insert — the end of the request (`app/apps/models.py`, `docs/reference/routing-outcomes.md` §3.2). Rows are bucketed by `ts` minus the row's recorded `latency_ms`, and the pinned caveat says that. Task 3: `test_c16_a_row_is_placed_by_its_estimated_arrival`, `test_c16_an_unusable_latency_subtracts_nothing`.
2. **Four limits, not three.** `output_tokens_per_minute` is added: generation throughput is how an on-prem engine's capacity is normally measured, and one total-token limit cannot express that completion tokens cost far more than prompt tokens. Task 2: `test_the_limits_are_a_closed_ordered_set`.
3. **The current arm's capacity comes from a `--capacity` file**, not from a block in the scenarios file (the brief offered both). It is a fact about the deployment, reused across proposals; one flag works in both modes; the scenarios schema keeps its closed key set. Task 3: `test_a_capacity_file_loads_and_is_hashed`. Task 6: `test_c1_a_capacity_file_adds_keys_and_changes_no_existing_value`.
4. **`volume_scale` exists in two places** — the file (both arms) and the proposal (proposed arm), multiplied. The brief named only `workload.volume_scale`. A proposal-only scale would compare a current arm at the recorded volume with a proposed arm at another, and the difference would read as the policy's effect. Task 3: `test_volume_scales_multiply_and_the_proposals_is_the_proposed_arm_only`.
5. **`volume_scale` and `capacity` are not in the `assumptions` block and not in the applied document.** `simulate._assumptions_summary` prints that block in every `simulation.json` with a fixed key set; a fourth key would break byte-identity. They are echoed in `edits` and in the capacity block. Task 2: `test_c1_capacity_and_volume_never_reach_the_applied_document`.
6. **`volume_scale` with no capacity stated is exit 2**, not a silent no-op; so is a capacity tuning flag with no capacity stated. Task 6: `test_c15_a_volume_scale_with_no_capacity_stated_is_refused`, `test_c15_a_tuning_flag_with_no_capacity_stated_is_refused`.
7. **Means and shares are over the buckets that hold traffic**, not over the whole window. An export of two sessions a week apart would otherwise have a mean of noise. Task 3: `test_a_gap_of_days_does_not_dilute_the_mean`, `test_a_mean_is_over_every_bucket_with_traffic_not_only_the_endpoints_own`.
8. **`on_overload` is not built**, and the roadmap's "predicted-rejection figure" is not produced (spec §9.2): the gateway would fail a refused request over, which replay does not follow; shedding at a hard limit is Erlang-B, not "the excess"; and `buckets_over_share` / `requests_over_share` already carry the exposure without asserting a behaviour. Task 3: `test_c10_no_key_ranks_recommends_or_prescribes` pins the exact key set.
9. **`ArmResult` gains `prompt_tokens` and `completion_tokens`**, defaulted and serialised nowhere, so demand counts the tokens that were costed. Task 1: `test_a_routed_arm_carries_the_tokens_it_was_priced_at`.
10. **Demand is reported for an endpoint with no stated limit**, without a utilisation. Task 3: `test_an_endpoint_with_demand_and_no_limit_is_shown_without_a_utilisation`.
11. **`latency_source` and `latency_exceeds_bucket` are reported per endpoint per arm.** Not in the brief; each marks a concurrency figure that rests on less than it appears to. Task 3: `test_an_asserted_latency_moves_concurrency_only`, `test_a_latency_longer_than_the_bucket_is_flagged`. Task 4: `test_an_endpoint_no_row_reaches_prints_zero_and_no_peak_bucket`.
12. **Capacity with `--shadow-prices` alone is refused**, not ignored: there is no proposed arm. Task 6: `test_c1_shadow_only_output_is_untouched_and_takes_no_capacity`.

One choice the brief left open and the spec settles the way the brief recommended, so it is not a deviation: **capacity figures get no range under `--uncertainty`** (spec §9.3). Task 5: `test_c9_ranges_and_capacity_together_leave_capacity_as_points`. Task 6: `test_c9_uncertainty_leaves_capacity_as_points`.

## Global Constraints

- **Offline only.** Touch `app/eval/`, `scripts/policy_simulate.py`, `tests/eval/` and `docs/`. No file under `app/` outside `app/eval/` changes. No serving module may import `app.eval` (`tests/eval/test_isolation.py` must keep passing); `app/eval` may import serving modules, never the reverse.
- **Pure router.** RouteForge deploys, scales and load-balances no inference. Nothing in this plan measures, reserves, enforces or manages capacity. Every limit is a figure the operator states; the code compares it with replayed demand and does nothing else. If a step seems to need admission control, a limiter or a call to an endpoint, stop: that is out of scope (B59 is the gateway's feature).
- **Opt-in and additive.** With no capacity stated — no `--capacity` and no `capacity` key in any proposal — every output file is byte-identical to what the tree produced before this plan. `tests/eval/test_uncertainty_golden.py` is that pin and this plan does not touch it. **The golden fixtures under `tests/eval/fixtures/` are never regenerated at head.** If the golden test fails in any task, the change that broke it is wrong.
- **RouteForge never ranks, recommends or prescribes.** Scenarios stay in file order. No output key or sentence of the capacity model contains `rank`, `recommend`, `best`, `winner`, `prefer`, `score`, `should`, `headroom`, `relax`, `gpu`, `buy` or `upgrade`. No output names a remedy, and a security requirement is never presented as the thing to change because capacity is short.
- **No predicted rejection, no delay, no range.** Do not add an overflow, shed, queue or wait figure, and do not put a `lo`/`hi` on a capacity figure. `newly_rejected` stays a policy figure.
- **Honesty about the figures.** `CAPACITY_CAVEAT` opens every capacity section and is pinned word for word; do not paraphrase it.
- **Exact values from the spec.** Limits, in this order: `max_concurrency`, `requests_per_minute`, `tokens_per_minute`, `output_tokens_per_minute`; each finite and `> 0`. `volume_scale`: finite, `0 < x ≤ 1_000_000`. Defaults: `--capacity-bucket 60` (integer, 1 to 86400), `--capacity-min-buckets 10` (integer ≥ 1). `SCHEMA = "routeforge.capacity-assumptions/v1"`, `METHOD = "bucketed_offered_load"`. `NOT_MODELLED = ("queueing", "batching", "autoscaling", "engine_concurrency", "external_load", "sub_bucket_bursts", "failover_load", "per_request_latency", "overload_behaviour")`. A bucket is over a limit when demand `> limit × (1 + 1e-9)`. Exit codes are unchanged: `0`, `2`, `3`, `4`.
- **Deterministic.** No clock, no randomness, no dict-order dependence in output. JSON is written as the existing code writes it (`json.dumps(..., sort_keys=True, indent=2)`), floats through `_round6` (`app/eval/outcomes.py`). Bucket arithmetic is in integer milliseconds.
- **Tests.** Always run pytest as `LITELLM_LOCAL_MODEL_COST_MAP=True uv run pytest ...`; without the variable pytest hangs on import. There is no pytest-asyncio: use `asyncio.run`. Shared simulator fixtures are in `tests/eval/sim_fixtures.py` (`BASE_SETTINGS`, `make_snapshot`, `app_entry`, `onboarded_row`, `make_row`). The commands below do not pass `-q`: `pyproject.toml` already sets it, and a second `-q` hides the summary line.
- **What each task runs.** The focused tests named in its steps, then `tests/eval` (about eight minutes; it prints `N passed`). The whole suite runs once, in Task 8, with `-rf`: it takes more than ten minutes and prints no summary line under `-q`, so `-rf` is what lists a failure. One failure is pre-existing and not caused by this branch: `tests/test_pii_detection_pipeline.py::test_engineering_labels_survive_gate_for_onprem_only_pii_off_app`.
- **Code style.** Type-hint everything. Match the surrounding comment density and idiom. `app/eval` modules import each other's underscore-private helpers (as `scenarios.py` and `shadow.py` already do); keep that idiom. No application name in a symbol, test id, fixture or comment (`.claude/skills/consumer-contract-tests`).

## Tasks

### Task 1: An arm carries the tokens it priced the call at (spec §5.1)

**Files:**
- Modify: `app/eval/simulate.py` (`ArmResult`, the last `return` of `simulate_row`)
- Create: `tests/eval/test_capacity_arm.py`

**Interfaces:**
- Consumes: `app/eval/simulate.py::simulate_row` — inside it, `prompt_tokens: int` (the billed prompt count scaled by `workload.token_scale`, or the routing count when no backend answered) and `completion_tokens: int` (the recorded count, or the router's output estimate when no backend answered) are the pair already passed to `price_call`. `simulate(records, snapshot, proposal, *, base) -> tuple[list[RowResult], dict[str, int]]`.
- Produces: two new `ArmResult` fields, after `quality_set_id`, both keyword-only in practice:
  - `prompt_tokens: int | None = None`
  - `completion_tokens: int | None = None`

  Set on a routed arm; `None` on a rejected arm and for every caller that builds an `ArmResult` without them. Serialised nowhere. Task 3's `arm_demand` reads them.

**Why first.** Demand must count the tokens that were costed. Recomputing them in the capacity module would need the scenario's settings and assumptions after replay has closed them, and would be a second copy of `simulate_row`'s arithmetic.

  - `capacity_block(results: list[RowResult], plan: CapacityPlan, proposal: dict | None = None, *, excluded: dict[str, int] | None = None) -> dict` — the block of spec §7.1. **Not rounded**; callers pass it through `_round6`.

**Rules.**

- Buckets are by **estimated arrival**: `ts` minus the row's recorded `latency_ms`, in integer milliseconds, floor-divided by the bucket. `ts` is when the row was written, the end of the request.
- "Buckets that hold traffic" are the buckets of **every** simulated row with a `ts`, routed or rejected. Means and shares divide by that count.
- A bucket is over a limit when demand `> limit × (1 + 1e-9)`. Exactly the limit is not over.
- With fewer than `plan.min_buckets` such buckets, return the head with `window_too_short: True`, `endpoints: {}` and both `peak` entries `None`. Compute no figure.
- The block's key set is exactly the one `test_c10_no_key_ranks_recommends_or_prescribes` lists. Do not add an overflow, rejection, shortfall or remedy field.
- The test module's helpers (`traffic`, `one_endpoint`, `three_endpoints`, `mixed_traffic`, `replay`, `block_for`, `keys_of`, `LIMITS`, `QUIET_THEN_BUSY`, `CAPACITY_BANNED`) are imported by Tasks 4–6. Every expected demand comes from the real replay.

def _totals(demand: dict) -> list[float]:
    return [sum(load[i] for buckets in demand.values() for load in buckets.values())
            for i in range(4)]

"""P3c-4: a capacity model for the policy simulator (offline, operator-run).

The simulator predicts routes, cost, latency and rejections under a policy
change. This module adds the question it could not answer: can the endpoints
that traffic lands on carry it?

**Stated capacity against replayed demand.** Nothing here is measured, and
nothing here manages capacity -- RouteForge deploys, scales and load-balances
no inference. An operator STATES limits for an endpoint (a `--capacity` file
for the deployment as it is, a proposal's `capacity` key for what a change
would make it), exactly as they state `workload.token_scale` or an
endpoint's `latency_ms`. Demand is computed from the rows replay already
routed: per arm, per endpoint, per time bucket.

    requests/min   = requests arriving in the bucket, per minute
    tokens/min     = prompt + completion tokens of those requests, per minute
    out tokens/min = completion tokens of those requests, per minute
    concurrency    = sum of their replayed latency / bucket length
                     (the Erlang offered load of the bucket)

Utilisation is demand divided by the stated limit. There is no queueing
model, no predicted rejection and no predicted delay: RouteForge does not
know what an endpoint does above a stated limit (`CAPACITY_CAVEAT`).

Never ranks a scenario and never proposes a remedy. Never imported by
serving code (`tests/eval/test_isolation.py`).
"""
from __future__ import annotations

import hashlib
import json
from collections.abc import Callable
from dataclasses import dataclass, field
from datetime import datetime, timezone

from app.eval.proposal import (CAPACITY_LIMITS, MAX_VOLUME_SCALE, ProposalError, _check_keys,
                               _finite_number, _opt_dict, validate_capacity_limits,
                               volume_scale_block)
from app.eval.scenario import ALL_APPS
from app.eval.simulate import RowResult, _parse_ts, _utc, replay_tokens

_SCHEMA_PREFIX = "routeforge.capacity-assumptions/"
_SCHEMA_MAJOR = "v1"
METHOD = "bucketed_offered_load"

DEFAULT_BUCKET_SECONDS = 60
MAX_BUCKET_SECONDS = 86_400
DEFAULT_MIN_BUCKETS = 10

ARMS = ("current", "proposed")
#: stated limit -> the demand it is compared with.
DEMAND_FOR = {"max_concurrency": "concurrency",
              "requests_per_minute": "requests_per_minute",
              "tokens_per_minute": "tokens_per_minute",
              "output_tokens_per_minute": "output_tokens_per_minute"}
DEMANDS = tuple(DEMAND_FOR[limit] for limit in CAPACITY_LIMITS)

#: What a capacity figure does NOT model, as stable ids for `capacity.not_modelled`.
NOT_MODELLED = ("queueing", "batching", "autoscaling", "engine_concurrency", "external_load",
                "sub_bucket_bursts", "failover_load", "per_request_latency",
                "overload_behaviour")

# A bucket is "over" a limit only when demand exceeds it by more than float
# noise: demand of exactly the limit is 100%, which is not above 100%.
_OVER = 1e-9


class CapacityError(ValueError):
    """A `--capacity` file load/validate error, or a capacity flag out of
    range. Always names the offending location, like `ProposalError`."""

    def __init__(self, where: str, message: str) -> None:
        self.where = where
        self.message = message
        super().__init__(f"{where}: {message}")


@dataclass(frozen=True)
class CapacityPlan:
    """Everything the capacity model was told, apart from what a proposal
    adds: the bucket length, the shortest window it will report on, and the
    BASE assumptions of a `--capacity` file -- limits and a volume scale
    that hold in BOTH arms. All empty without a file."""

    bucket_seconds: int = DEFAULT_BUCKET_SECONDS
    min_buckets: int = DEFAULT_MIN_BUCKETS
    limits: dict[str, dict[str, float]] = field(default_factory=dict)
    volume: dict[str, float] = field(default_factory=dict)
    file_sha256: str | None = None

    def __post_init__(self) -> None:
        for flag, value, top in (("--capacity-bucket", self.bucket_seconds, MAX_BUCKET_SECONDS),
                                 ("--capacity-min-buckets", self.min_buckets, None)):
            if (not isinstance(value, int) or isinstance(value, bool) or value < 1
                    or (top is not None and value > top)):
                raise CapacityError(
                    flag, "must be an integer >= 1" + (f" and <= {top}" if top else ""))


def load_capacity(path: str) -> tuple[dict, str]:
    """Read a `--capacity` JSON file. Returns `(doc, sha256 hex)` -- the hash
    is over the raw file bytes. Shape only: the schema, the closed key sets
    and every value's range. `build_plan` checks it against a snapshot."""
    with open(path, "rb") as f:
        raw = f.read()
    digest = hashlib.sha256(raw).hexdigest()
    try:
        doc = json.loads(raw)
    except json.JSONDecodeError as exc:
        raise CapacityError("file", f"invalid JSON: {exc}") from exc
    try:
        _validate_file(doc)
    except ProposalError as exc:
        raise CapacityError(exc.where, exc.message) from exc
    return doc, digest


def _validate_file(doc) -> None:
    schema = doc.get("schema") if isinstance(doc, dict) else None
    if not isinstance(schema, str) or not schema.startswith(_SCHEMA_PREFIX):
        raise CapacityError("schema", f"must start with {_SCHEMA_PREFIX!r}; got {schema!r}")
    major = schema[len(_SCHEMA_PREFIX):].split(".", 1)[0]
    if major != _SCHEMA_MAJOR:
        raise CapacityError("schema", f"major version must be {_SCHEMA_MAJOR!r}; got {major!r}")
    _check_keys(doc, _TOP_KEYS, "")
    if doc.get("title") is not None and not isinstance(doc["title"], str):
        raise CapacityError("title", "must be a string")
    for slug, limits in _opt_dict(doc, "endpoints", "endpoints").items():
        validate_capacity_limits(f"endpoints.{slug}", limits)
    workload = _opt_dict(doc, "workload", "workload")
    _check_keys(workload, _WORKLOAD_KEYS, "workload")
    _validate_volume("workload", workload)
    for app_id, fields in _opt_dict(workload, "apps", "workload.apps").items():
        _check_keys(fields, _WORKLOAD_APP_KEYS, f"workload.apps.{app_id}")
        _validate_volume(f"workload.apps.{app_id}", fields)


def _validate_volume(loc: str, fields: dict) -> None:
    if "volume_scale" in fields:
        value = fields["volume_scale"]
        if not (_finite_number(value) and 0 < value <= MAX_VOLUME_SCALE):
            raise CapacityError(f"{loc}.volume_scale",
                                f"must be a finite number > 0 and <= {MAX_VOLUME_SCALE}")


def build_plan(doc: dict | None, sha256: str | None, snapshot: dict, *,
               bucket_seconds: int = DEFAULT_BUCKET_SECONDS,
               min_buckets: int = DEFAULT_MIN_BUCKETS) -> CapacityPlan:
    """The plan for one run. `doc` is a loaded `--capacity` file or None.
    Every endpoint it names must be in `snapshot` -- an onboarded row
    (enabled or not) or a priced YAML pool model -- and every application
    too: a typo must never read as "no limit stated"."""
    if doc is None:
        return CapacityPlan(bucket_seconds=bucket_seconds, min_buckets=min_buckets)
    pricing = snapshot["settings"].get("pricing")
    priced = pricing.get("models") if isinstance(pricing, dict) else None
    known = ({row["slug"] for row in snapshot["onboarded"]}
             | (set(priced) if isinstance(priced, dict) else set()))
    limits: dict[str, dict[str, float]] = {}
    for slug, stated in sorted((doc.get("endpoints") or {}).items()):
        if slug not in known:
            raise CapacityError(f"endpoints.{slug}",
                                "not an onboarded endpoint or a priced model in the snapshot")
        limits[slug] = {key: float(stated[key]) for key in CAPACITY_LIMITS if key in stated}
    app_ids = {entry["application_id"] for entry in snapshot["apps"]}
    workload = doc.get("workload") or {}
    for app_id in workload.get("apps") or {}:
        if app_id == ALL_APPS:
            raise CapacityError(f"workload.apps.{app_id}",
                                "application id '*' is reserved for the global value")
        if app_id not in app_ids:
            raise CapacityError(f"workload.apps.{app_id}", "unknown application")
    return CapacityPlan(bucket_seconds=bucket_seconds, min_buckets=min_buckets, limits=limits,
                        volume=volume_scale_block(workload), file_sha256=sha256)


def plan_inputs(plan: CapacityPlan) -> dict:

    return {"file_sha256": plan.file_sha256, "bucket_seconds": plan.bucket_seconds,
            "min_buckets": plan.min_buckets}

# --- demand (spec §5) -----------------------------------------------------------

def arrival_bucket(row: dict, bucket_seconds: int) -> int | None:
    """The index of the bucket `row` ARRIVED in, or None when it has no `ts`.

    `ts` is when the outcome row was written -- the END of the request
    (`docs/reference/routing-outcomes.md` §3.2). Arrival is estimated as `ts`
    minus the row's recorded `latency_ms`; a missing, negative or non-finite
    latency subtracts nothing. Buckets are aligned to the Unix epoch, so a
    row's bucket does not depend on which other rows the export holds.
    Integer milliseconds throughout: no float decides a boundary."""
    ts = row.get("ts")
    if not ts:
        return None
    written_ms = round(_utc(_parse_ts(ts)).timestamp() * 1000)
    latency = row.get("latency_ms")
    service_ms = round(latency) if _finite_number(latency) and latency > 0 else 0
    return (written_ms - service_ms) // (bucket_seconds * 1000)


def bucket_start(index: int, bucket_seconds: int) -> str:
    """A bucket's start as an ISO-8601 UTC timestamp."""
    return datetime.fromtimestamp(index * bucket_seconds, tz=timezone.utc).isoformat()


def volume_for(volume: dict[str, float], app_id: str) -> float:
    """The app's own `volume_scale`, else the global one, else 1.0."""
    return volume.get(app_id, volume.get(ALL_APPS, 1.0))


#: One endpoint's load in one bucket: `[requests, tokens, output_tokens, busy_ms]`.
Load = list[float]


def arm_demand(results: list[RowResult], arm: str, *, bucket_seconds: int,
               volume: Callable[[str], float]) -> dict[str, dict[int, Load]]:
    """`{endpoint: {bucket: Load}}` for one arm: every row the arm ROUTED,
    added to the endpoint replay served it from, in the bucket it arrived
    in, `volume(application_id)` times. A rejected row adds nothing; a row
    with no `ts` cannot be placed and adds nothing (the block counts those).
    Tokens are the counts the arm priced the call at (`ArmResult`)."""
    demand: dict[str, dict[int, Load]] = {}
    for r in results:
        result = getattr(r, arm)
        if result.outcome != "routed":
            continue
        bucket = arrival_bucket(r.row, bucket_seconds)
        if bucket is None:
            continue
        times = volume(r.row["application_id"])
        completion = result.completion_tokens or 0
        load = demand.setdefault(result.model, {}).setdefault(bucket, [0.0, 0.0, 0.0, 0.0])
        load[0] += times
        load[1] += times * ((result.prompt_tokens or 0) + completion)
        load[2] += times * completion
        load[3] += times * (result.latency_ms or 0.0)
    return demand


def _rates(load: Load, bucket_seconds: int) -> dict[str, float]:
    """One bucket's load as the four demands, each in its limit's unit."""
    per_minute = 60.0 / bucket_seconds
    return {"concurrency": load[3] / (bucket_seconds * 1000.0),
            "requests_per_minute": load[0] * per_minute,
            "tokens_per_minute": load[1] * per_minute,
            "output_tokens_per_minute": load[2] * per_minute}


def _latencies(results: list[RowResult], arm: str) -> dict[str, tuple[float, str | None]]:
    """The one `(latency_ms, source)` replay gave each endpoint in `arm`:
    the first routed row's. Replay's ladder is a function of the endpoint
    alone -- `proposal`, `observed`, `signal` or `tier_default`."""
    out: dict[str, tuple[float, str | None]] = {}
    for r in results:
        result = getattr(r, arm)
        if result.outcome == "routed" and result.latency_ms is not None:
            out.setdefault(result.model, (float(result.latency_ms), result.latency_source))
    return out


def _arm_block(buckets: dict[int, Load], limits: dict[str, float],
               replayed: tuple[float, str | None] | None, *,
               active: int, bucket_seconds: int) -> dict:
    """One endpoint in one arm: demand per dimension, and utilisation of
    each STATED limit. `active` is the number of buckets the export has any
    traffic in -- the same denominator for every endpoint and both arms."""
    latency, source = replayed if replayed is not None else (None, None)
    rates = {index: _rates(load, bucket_seconds) for index, load in sorted(buckets.items())}
    requests = sum(load[0] for load in buckets.values())
    demand = {}
    for name in DEMANDS:
        values = [rate[name] for rate in rates.values()]
        demand[name] = {"peak": max(values, default=0.0), "mean": sum(values) / active}
    stated = {}
    for limit in CAPACITY_LIMITS:
        if limit not in limits:
            continue
        cap, name = limits[limit], DEMAND_FOR[limit]
        peak_at = None
        for index, rate in rates.items():           # ascending: the earliest peak wins
            if rate[name] > (rates[peak_at][name] if peak_at is not None else 0.0):
                peak_at = index
        over = [index for index, rate in rates.items() if rate[name] > cap * (1 + _OVER)]
        stated[limit] = {
            "limit": cap,
            "peak": demand[name]["peak"] / cap,
            "mean": demand[name]["mean"] / cap,
            "peak_bucket": None if peak_at is None else bucket_start(peak_at, bucket_seconds),
            "buckets_over": len(over),
            "buckets_over_share": len(over) / active,
            "requests_over_share": (sum(buckets[index][0] for index in over) / requests
                                    if requests else None),
        }
    return {"requests": requests, "latency_ms": latency, "latency_source": source,
            "latency_exceeds_bucket": latency is not None and latency > bucket_seconds * 1000,
            "demand": demand, "limits": stated}


def _peak(endpoints: dict, arm: str) -> dict | None:
    """The most loaded STATED limit of `arm`: the largest peak utilisation,
    the first in (endpoint, `CAPACITY_LIMITS`) order on a tie. None when the
    arm has no stated limit at all."""
    top = None
    for slug in sorted(endpoints):
        for limit, entry in endpoints[slug][arm]["limits"].items():
            if top is None or entry["peak"] > top["utilisation"]:
                top = {"endpoint": slug, "limit": limit, "utilisation": entry["peak"],
                       "bucket": entry["peak_bucket"]}
    return top


#: Excluded rows that load no endpoint inside the window, so are not "missing demand".
_NOT_DEMAND = ("cache_hit", "before_since")


def capacity_block(results: list[RowResult], plan: CapacityPlan, proposal: dict | None = None,
                   *, excluded: dict[str, int] | None = None) -> dict:
    """The `capacity` block for one proposal (spec §7).

    The `current` arm is measured against the plan's base limits at the
    base volume. The `proposed` arm is measured against the base limits
    overridden, limit by limit, by the proposal's `capacity`, at the base
    volume TIMES the proposal's `workload.volume_scale`.

    With fewer than `plan.min_buckets` buckets holding any traffic the block
    says `window_too_short` and carries no endpoint figure at all."""
    proposal = proposal or {}
    bucket_seconds = plan.bucket_seconds
    proposal_volume = volume_scale_block(proposal.get("workload"))
    stamped = [arrival_bucket(r.row, bucket_seconds) for r in results]
    active = sorted({index for index in stamped if index is not None})
    too_short = len(active) < plan.min_buckets
    block = {
        "method": METHOD,
        "bucket_seconds": bucket_seconds,
        "min_buckets": plan.min_buckets,
        "window": {
            "first_bucket": bucket_start(active[0], bucket_seconds) if active else None,
            "last_bucket": bucket_start(active[-1], bucket_seconds) if active else None,
            "buckets": active[-1] - active[0] + 1 if active else 0,
            "active_buckets": len(active)},
        "rows": {
            "simulated": len(results),
            "without_ts": stamped.count(None),
            "estimated_tokens": sum(1 for r, index in zip(results, stamped)
                                    if index is not None and replay_tokens(r.row)[2]),
            "excluded_not_counted": sum(n for reason, n in (excluded or {}).items()
                                        if reason not in _NOT_DEMAND)},
        "volume_scale": {"base": dict(plan.volume), "proposal": proposal_volume},
        "not_modelled": list(NOT_MODELLED),
        "window_too_short": too_short,
        "endpoints": {},
        "peak": {arm: None for arm in ARMS},
    }
    if too_short:
        return block

    stated = proposal.get("capacity") or {}
    limits = {"current": plan.limits,
              "proposed": {slug: {**plan.limits.get(slug, {}),
                                  **{key: float(value)
                                     for key, value in stated.get(slug, {}).items()}}
                           for slug in {*plan.limits, *stated}}}
    volumes = {"current": lambda app_id: volume_for(plan.volume, app_id),
               "proposed": lambda app_id: (volume_for(plan.volume, app_id)
                                           * volume_for(proposal_volume, app_id))}
    demand = {arm: arm_demand(results, arm, bucket_seconds=bucket_seconds, volume=volumes[arm])
              for arm in ARMS}
    latency = {arm: _latencies(results, arm) for arm in ARMS}
    slugs = sorted({slug for arm in ARMS for slug in (*demand[arm], *limits[arm])})
    block["endpoints"] = {
        slug: {arm: _arm_block(demand[arm].get(slug, {}), limits[arm].get(slug, {}),
                               latency[arm].get(slug), active=len(active),
                               bucket_seconds=bucket_seconds)
               for arm in ARMS}
        for slug in slugs}
    block["peak"] = {arm: _peak(block["endpoints"], arm) for arm in ARMS}
    return block
````

+    the rows that could not be counted."""
+    window, rows = block["window"], block["rows"]
+    lines = [f"Buckets of {block['bucket_seconds']} s by estimated arrival time. "
+             f"{window['active_buckets']} of {window['buckets']} bucket(s) in the window hold "
+             f"traffic" + (f" ({window['first_bucket']} to {window['last_bucket']})"
+                           if window["active_buckets"] else "")
+             + f"; {rows['simulated']} simulated row(s). Means are over the buckets that hold "
+             "traffic.", ""]
+    if block["volume_scale"]["base"]:
+        lines += ["Volume scale stated for both arms: "
+                  f"{_scale_text(block['volume_scale']['base'])}.", ""]
+    if rows["without_ts"]:
+        lines += [f"**Note:** {rows['without_ts']} simulated row(s) have no timestamp and are "
+                  "in no bucket: demand is understated by them.", ""]
+    if rows["excluded_not_counted"]:
+        lines += [f"**Note:** {rows['excluded_not_counted']} excluded row(s) (see \"Excluded "
+                  "rows\") may have loaded an endpoint and are not in the demand.", ""]
+    if rows["estimated_tokens"]:
+        lines += [f"**Note:** {rows['estimated_tokens']} row(s) have no backend token count; "
+                  "their token demand is RouteForge's own estimate.", ""]
+    return lines
+
+
+def _limit_rows(entry: dict, active: int) -> list[str]:
+    rows = []
+    for limit in CAPACITY_LIMITS:
+        for arm in ARMS:
+            stated = entry[arm]["limits"].get(limit)
+            if stated is None:
+                if limit in entry["current"]["limits"] or limit in entry["proposed"]["limits"]:
+                    rows.append(f"| {limit} | {arm} | not stated | n/a | n/a | n/a | n/a | n/a |")
+                continue
+            rows.append(
+                f"| {limit} | {arm} | {_num(stated['limit'])} | {_pct(stated['peak'])} | "
+                f"{_pct(stated['mean'])} | {stated['buckets_over']} of {active} | "
+                f"{_pct(stated['requests_over_share'])} | {stated['peak_bucket'] or 'n/a'} |")
+    return rows
+
+
+def endpoint_lines(slug: str, entry: dict, block: dict, *, depth: int) -> list[str]:
+    """One endpoint: requests and latency per arm, utilisation of each
+    stated limit, then the demand itself (stated limit or not)."""
+    current, proposed = entry["current"], entry["proposed"]
+    lines = [f"{'#' * depth} {slug}", "",
+             f"Requests: current {_num(current['requests'])}, proposed "
+             f"{_num(proposed['requests'])}. Replayed latency: current "
+             f"{_latency_text(current)}, proposed {_latency_text(proposed)}.", ""]
+    for arm in ARMS:
+        if entry[arm]["latency_source"] == "tier_default":
+            lines += [f"**Note:** the {arm} arm's latency for this endpoint is a tier default, "
+                      "not a measurement: its offered concurrency rests on that default alone.",
+                      ""]
+        if entry[arm]["latency_exceeds_bucket"]:
+            lines += [f"**Note:** the {arm} arm's replayed latency is longer than a bucket, so a "
+                      "request's whole service time is counted in the bucket it arrived in. "
+                      "A longer `--capacity-bucket` avoids that.", ""]
+    limit_rows = _limit_rows(entry, block["window"]["active_buckets"])
+    if limit_rows:
+        lines += ["| limit | arm | stated | peak | mean | buckets over 100% | "
+                  "requests in those buckets | peak bucket |",
+                  "|---|---|---|---|---|---|---|---|", *limit_rows, ""]
+    else:
+        lines += ["No limit is stated for this endpoint; demand only.", ""]
+    lines += ["| demand | current peak | current mean | proposed peak | proposed mean |",
+              "|---|---|---|---|---|"]
+    for name in DEMANDS:
+        lines.append(f"| {name} | {_num(current['demand'][name]['peak'])} | "
+                     f"{_num(current['demand'][name]['mean'])} | "
+                     f"{_num(proposed['demand'][name]['peak'])} | "
+                     f"{_num(proposed['demand'][name]['mean'])} |")
+    lines.append("")
+    return lines
+
+
+def scenario_lines(block: dict, *, depth: int) -> list[str]:
+    """One proposal's (or one scenario's) capacity figures: its own volume
+    scale, each arm's peak load, then every endpoint -- or the
+    window-too-short state and nothing else."""
+    lines = []
+    if block["volume_scale"]["proposal"]:
+        lines += [f"Volume scale assumed by the proposal (proposed arm only, multiplying any "
+                  f"stated for both arms): {_scale_text(block['volume_scale']['proposal'])}.", ""]
+    if block["window_too_short"]:
+        return lines + [f"No utilisation figure: {too_short_text(block)}. "
+                        "`--capacity-min-buckets` sets the number needed.", ""]
+    lines += [f"Peak load: current {peak_text(block, 'current')}; proposed "
+              f"{peak_text(block, 'proposed')}.", ""]
+    for slug in sorted(block["endpoints"]):
+        lines += endpoint_lines(slug, block["endpoints"][slug], block, depth=depth)
+    return lines
+
+
+def intro_lines(block: dict, *, ranged: bool) -> list[str]:
+    """The top of a capacity section: the caveat, the no-remedy sentence,
+    the shared window, and -- with `--uncertainty` -- why there is no range."""
+    lines = [*caveat_lines(), "", NO_REMEDY_NOTE, "", *window_lines(block)]
+    if ranged:
+        lines += [NO_RANGE_NOTE, ""]
+    return lines
+
+
+def render_capacity_section(block: dict, *, ranged: bool = False) -> str:
+    """The `## Capacity` section of a single-proposal report. `ranged` is
+    True when the same report also carries `--uncertainty` ranges. Ends with
+    exactly one newline."""
+    lines = ["## Capacity", "", *intro_lines(block, ranged=ranged),
+             *scenario_lines(block, depth=3)]
+    return "\n".join(lines).rstrip("\n") + "\n"
````

+## 11. Capacity: stated limits against replayed demand (P3c-4)
+
+Design: `docs/superpowers/specs/2026-10-07-p3c4-capacity-design.md`. Research notes:
+`docs/research/feasible-route-bench.md` §21. Code: `app/eval/capacity.py` (`CapacityPlan`,
+`load_capacity`, `build_plan`, `arm_demand`, `capacity_block`, `render_capacity_section`),
+wired into `app/eval/scenarios.py` and `scripts/policy_simulate.py`.
+
+### 11.1 What it answers
+
+§4–§10 say where requests would go and what that costs. They treat every endpoint as having
+unlimited room. This section answers the other half: **would the endpoints the traffic lands
+on be able to carry it?** — "all healthcare traffic on-prem" can be cheaper, safer and still
+put one local endpoint at 230% of what it can serve.
+
+It is a comparison of two things, and only that:
+
+- **capacity the operator states** — RouteForge measures none of it and manages none of it
+  (it deploys, scales and load-balances no inference);
+- **demand the replay predicts** — the rows the simulator already routed, per endpoint, per
+  arm, per time bucket.
+
+It is **off unless a capacity is stated**: a `--capacity` file, or a `capacity` key in the
+proposal or in any scenario. With none, every output file is byte-identical to what it was
+before this feature (`tests/eval/test_uncertainty_golden.py` still pins that).
+
+### 11.2 Stating capacity
+
+**The deployment as it is — `--capacity FILE`**, schema
+`routeforge.capacity-assumptions/v1`:
+
+```json
+{
+  "schema": "routeforge.capacity-assumptions/v1",
+  "title": "Lab endpoints, as load-tested 2026-10",
+  "endpoints": {
+    "local-llama": {"max_concurrency": 8, "requests_per_minute": 600,
+                    "tokens_per_minute": 400000, "output_tokens_per_minute": 90000}
+  },
+  "workload": {"volume_scale": 10, "apps": {"claims": {"volume_scale": 25}}}
+}
+```
+
+- Keys: `schema`, `title` (optional), `endpoints`, `workload`. Anything else is a load error.
+- `endpoints.<slug>` must be an onboarded row of the snapshot (enabled or not) or a priced
+  YAML pool model. A slug the snapshot does not hold is a load error — a typo never reads as
+  "no limit stated".
+- What the file states holds in **both arms**.
+
+**What a change would make it — the proposal's `capacity` key** (§2.1): the same four limits
+per slug, for the **proposed arm only**, overriding the file **limit by limit**. The slug
+must exist in the proposed arm (an onboarded row the proposal does not remove, a priced pool
+model, or an endpoint the proposal adds).
+
+**The four limits.** Each is optional, and a finite number `> 0`:
+
+| Limit | Compared with, per bucket |
+|---|---|
+| `max_concurrency` | offered concurrency: the service time arriving in the bucket ÷ the bucket length |
+| `requests_per_minute` | requests arriving, per minute |
+| `tokens_per_minute` | prompt + completion tokens of those requests, per minute |
+| `output_tokens_per_minute` | completion tokens of those requests, per minute |
+
+**A limit of `0` is refused**, not read as "no capacity". Leave the key out for "not stated".
+
+### 11.3 Volume scale
+
+`volume_scale` (finite, `0 < x ≤ 1,000,000`, default `1`) counts every routed request of an
+application that many times. It has a global value and per-application overrides, and can be
+set in two places:
+
+| Where | Applies to | Reads as |
+|---|---|---|
+| the `--capacity` file's `workload` | both arms | "real traffic is this many times the export" |
+| a proposal's `workload` | the proposed arm | "…and suppose it grew by this much" |
+
+The proposed arm's factor for an application is the product of the two.
+
+- It changes **no route and no cost figure**. Everything outside the capacity section is for
+  the recorded volume.
+- It does **not rescale burstiness**: ten times the volume is the same arrivals, each counted
+  ten times.
+- It does **not make a small export a large one**: 24 rows at `volume_scale: 1000` are 24
+  arrival times. The window-too-short rule (§11.5) counts buckets, not scaled requests.
+- `workload.token_scale` scales the prompt tokens in token demand (then `volume_scale`
+  multiplies); it moves neither the request rate nor the replayed latency.
+- Setting it with no capacity stated anywhere is exit `2`: it would change nothing.
+

+### 11.5 The method
+
+- **Which rows.** For each arm, every simulated row the arm **routed** adds demand to the
+  endpoint replay served it from. A rejected row adds nothing.
+- **When.** `ts` on an outcome row is when the row was **written — the end of the request**.
+  Arrival is estimated as `ts` minus the row's recorded `latency_ms`. Buckets are aligned to
+  the Unix epoch (with the default, a bucket is a UTC minute). A row with no `ts` is counted
+  in `rows.without_ts` and is in no bucket.
+- **Tokens.** The counts replay **priced** the call at: the backend's billed prompt count
+  (scaled by `token_scale`) and the recorded completion count. A row no backend answered uses
+  RouteForge's own `routing_tokens` and the router's output estimate (§6); those rows are
+  counted in `rows.estimated_tokens`. `tokens_per_minute` is prompt + completion, as a
+  provider's TPM quota counts a call; a provider that reserves `max_tokens` at admission
+  counts more. Cached tokens are not subtracted.
+- **Latency.** Offered concurrency uses the arm's **replayed** latency for the endpoint.
+  Replay gives each endpoint **one** latency (asserted `latency_ms`, else the median observed,
+  else the signal, else the tier default — `latency_source`), so offered concurrency is the
+  request rate times a constant. **A row moved to an endpoint it never ran on gets that
+  endpoint's latency.** A `tier_default` latency has no measurement behind it, and a latency
+  longer than a bucket piles a request's whole service time into the bucket it arrived in;
+  the report notes both.
+- **Means are over the buckets that hold traffic** — the buckets in which any simulated row
+  arrived, the same set for both arms and every endpoint. An export of two sessions a week
+  apart is not averaged over the empty week. `window.buckets` and `window.active_buckets`
+  show how sparse the export is.
+- **Window too short.** With fewer than `--capacity-min-buckets` buckets holding traffic the
+  block says `window_too_short: true` and carries no endpoint figure; the comparison table
+  cell reads `window too short (k of the 10 buckets needed)`.
+
+Per endpoint, per arm, per **stated** limit: `limit`, `peak` (the busiest bucket ÷ the
+limit), `mean`, `peak_bucket`, `buckets_over` and `buckets_over_share` (buckets above 100%),
+and `requests_over_share` (that endpoint's requests arriving in those buckets). Demand of
+exactly the limit is 100%, which is not above it. Demand itself (`peak`, `mean` of each of
+the four) is shown for every endpoint with routed rows, **stated limit or not**.
+
+### 11.6 What the figures are — and are not
+
+Every capacity section opens with this, verbatim:
+
+> **Stated capacity against replayed demand.** Every limit below is a figure the operator
+> stated; RouteForge has not measured it and does not manage capacity. Demand is the replayed
+> route of each recorded request, grouped into buckets by estimated arrival time (the time
+> the record was written minus its recorded latency). Nothing here models queueing, batching,
+> autoscaling, the serving engine's real concurrency behaviour, load that reaches an endpoint
+> without passing through RouteForge, bursts shorter than a bucket, or the load of failover
+> attempts. Replay gives each endpoint one latency, so offered concurrency is the request
+> rate times that latency. RouteForge does not know what an endpoint does above a stated
+> limit (queue, shed or slow down), so no rejection and no delay is predicted. An export of
+> a few buckets says little.

+`autoscaling`, `engine_concurrency`, `external_load`, `sub_bucket_bursts`, `failover_load`,
+`per_request_latency`, `overload_behaviour`.

+  block counts a request as lost: live, a refused request fails over to the next candidate,
+  which replay does not model.

+  why: the bootstrap resamples rows as if their order did not matter, and capacity depends on
+  when requests arrive. The capacity block is identical with and without `--uncertainty`, and
+  the `uncertainty` block is identical with and without capacity.

+  change to any policy or protection. The comparison table stays in file order; a lower peak
+  load does not make a scenario the one to choose.
+

+### 21.1 The model
+
+Let the export hold simulated rows `r`, each with a write time `ts(r)`, a recorded latency
+`ℓ(r)` and an application `app(r)`. Replay is a deterministic map from a row and an arm
+`a ∈ {current, proposed}` to either a rejection or a served endpoint `e_a(r)` with the token
+counts the call was priced at, `p_a(r)` (prompt) and `c_a(r)` (completion). Replay also
+assigns each endpoint one latency per arm, `L_a(e)` (§15: asserted, else median observed,
+else signal, else tier default).
+
+**Arrival.** `ts` is the time the record was written, which is the end of the request. The
+arrival estimate is `t(r) = ts(r) − ℓ(r)`, a property of the request and so the same in both
+arms. With bucket length `T`, the row's bucket is `b(r) = ⌊t(r) / T⌋`, aligned to the Unix
+epoch.
+
+**Demand.** With `v_a(r)` the volume scale of the row's application in arm `a` (§21.2), the
+four demands of endpoint `e` in bucket `b` are sums over `R_a(e, b) = {r : e_a(r) = e,
+b(r) = b}`:
+
+```
+requests/min        N_a(e,b) = (60/T) · Σ v_a(r)
+tokens/min          K_a(e,b) = (60/T) · Σ v_a(r) · (p_a(r) + c_a(r))
+output tokens/min   O_a(e,b) = (60/T) · Σ v_a(r) · c_a(r)
+offered concurrency A_a(e,b) = (1/T)  · Σ v_a(r) · L_a(e)        (L in seconds)
+```
+
+`A` is the Erlang offered load of the bucket: service time arriving per unit time, which is
+the mean number in service of an infinite-server system fed the same arrivals. Because `L`
+is constant per endpoint, `A_a(e,b) = N_a(e,b) · L_a(e) / 60`: offered concurrency carries
+the request rate and one number, nothing about the distribution of service times.
+
+**Utilisation.** Let `B` be the set of buckets in which any simulated row arrived (routed or
+not; the same for both arms and every endpoint). For a stated limit `C` on demand `D`:
+
+```
+peak  = max_{b ∈ B} D(e,b) / C
+mean  = (Σ_{b ∈ B} D(e,b) / |B|) / C
+buckets_over_share  = |{b ∈ B : D(e,b) > C}| / |B|
+requests_over_share = Σ_{b : D(e,b) > C} Σ_{R(e,b)} v(r)  /  Σ_b Σ_{R(e,b)} v(r)
+```
+
+Means are over `B`, not over the span from the first bucket to the last: an export of two
+sessions a week apart has ten thousand one-minute buckets in its span and twenty in `B`.
+
+**Window too short.** If `|B| < m` (`--capacity-min-buckets`, default 10) no figure is
+computed. The state is `window_too_short`, not a number.
+
+### 21.2 Volume scale
+
+`v_a(r)` is a product of two operator-stated factors: `s_0(app)` from the capacity file,
+applied in both arms ("the real volume is `s_0` times the export"), and `s_1(app)` from the
+proposal, applied in the proposed arm only ("and suppose it grew by `s_1`"). Each resolves
+per application, else globally, else to 1.
+
+Every demand is linear in `v`, so utilisation is linear in a global scale and the model's
+answer to "at what multiple of today's traffic does this endpoint reach 100% in its busiest
+bucket" is `1 / peak`. That is all the scale does. It thins or thickens the recorded
+arrivals in place: it does not model that a tenfold stream is smoother within a bucket, and
+it cannot create arrival times an export does not have. It moves no route and no cost; only
+the capacity section reads it.
+
+### 21.3 What it deliberately is not
+
+- **Not a queueing model.** There is no waiting time and no blocking probability. With a
+  hard concurrency limit and no queue the blocked share is Erlang-B in `A` and the limit; it
+  is above zero below 100% utilisation and depends on arrival variability that a bucketed
+  count with one service time per endpoint does not carry. Reporting "the excess over the
+  limit" as lost requests would be a lower bound presented as an estimate.
+- **Not a prediction of what overload does.** RouteForge does not know whether an endpoint
+  queues, sheds or slows down. And its own gateway would not simply lose a refused request:
+  it fails over, which first-decision replay does not follow. So no rejection figure is
+  derived from capacity, and `newly_rejected` stays a policy figure.
+- **Not a measurement of capacity.** Every limit is stated by the operator. RouteForge
+  manages no capacity and verifies no declaration.
+- **Not ranged.** The P3c-3 bootstrap (§20) resamples rows within an application as if their
+  order did not matter. Capacity depends on the order: a resample changes how many rows fall
+  in each bucket at random, and a peak is a maximum, for which a percentile bootstrap is a
+  poor estimator anyway. Capacity figures are points; a block bootstrap over time buckets is
+  the appropriate method and is not built.
+- **Not a recommendation.** No remedy is named, scenarios stay in file order, and no
+  requirement is presented as the thing to change because capacity is short.

+### 21.6 Limits
+
+- **No queue, no blocking, no delay**, and no statement of what an endpoint does above a
+  stated limit (§21.3).
+- **One service time per endpoint.** `A = N · L / 60`. Two deployments with the same request
+  rate and the same median latency have the same offered concurrency whatever their
+  latency distributions, and a row moved to another endpoint is given that endpoint's
+  latency rather than a prediction of its own. An endpoint with no observed latency is
+  given its tier default; the output flags that (`latency_source`).
+- **Arrival is estimated**, and a request longer than a bucket has its whole service time
+  counted in the bucket it arrived in (flagged, `latency_exceeds_bucket`).
+- **Demand is first-decision demand.** Failover attempts, hedged calls and anything that
+  does not pass through RouteForge are absent; so are rows excluded from simulation, which
+  are counted (`excluded_not_counted`).
+- **A stated limit is one number.** Real capacity depends on the lengths being served, the
+  batch size and the engine; a `max_concurrency` measured on short prompts overstates what
+  the endpoint carries on long ones.
+- **`volume_scale` multiplies; it does not generate traffic** (§21.2).
+- **Ten buckets is a floor**, not evidence that eleven describe a deployment.
+- **No range**, and none can be had from the row bootstrap of §20 (§21.3).
+- Everything in §21.5.1 is synthetic. Every figure on recorded traffic is **TO MEASURE**
+  (§21.5.2).

"""Modelling sanity check for the P3c-4 capacity engine. Not committed.

Two exports whose answer is known without running the code:

1. A step pattern -- 20 minutes at 2 requests a minute, then 10 at 12, each
   request 6 s -- computed by hand in the plan (Task 8, Step 3).
2. Poisson arrivals at rate LAMBDA with a constant service time S. Queueing
   theory gives the mean offered load LAMBDA x S exactly, and the count in a
   bucket of T seconds is Poisson(LAMBDA x T), so the share of buckets above
   a limit is a Poisson tail.

Both are replayed through the real simulator, then through the capacity
engine.

import asyncio
import math
import random
from datetime import datetime, timedelta, timezone

from app.eval.capacity import CapacityPlan, capacity_block
from app.eval.simulate import simulate
from tests.eval.sim_fixtures import (BASE_SETTINGS, app_entry, make_row, make_snapshot,
                                     onboarded_row)

P = "routeforge.policy-proposal/v1"
T0 = datetime(2026, 9, 20, 12, 0, tzinfo=timezone.utc)
SNAPSHOT = make_snapshot(onboarded=[onboarded_row("local-cheap", "cheap")],
                         apps=[app_entry("app-a")])


def row(i: int, arrival: datetime, latency_ms: float) -> dict:
    written = arrival + timedelta(milliseconds=latency_ms)
    return make_row(f"r{i:05d}", "app-a", ts=written.isoformat(), latency_ms=latency_ms,
                    prompt_tokens=900, completion_tokens=100)


def block(rows: list[dict], limits: dict, body: dict | None = None) -> dict:
    results, excluded = asyncio.run(simulate(rows, SNAPSHOT, {"schema": P, **(body or {})},
                                             base=BASE_SETTINGS))
    return capacity_block(results, CapacityPlan(limits={"local-cheap": limits}), body,
                          excluded=excluded)


def step_pattern() -> None:
    rows, i = [], 0
    for minute, count in enumerate([2] * 20 + [12] * 10):
        for j in range(count):
            rows.append(row(i, T0 + timedelta(minutes=minute, seconds=5 + 4 * j), 6000.0))
            i += 1
    out = block(rows, {"max_concurrency": 1.0, "output_tokens_per_minute": 500.0},
                {"workload": {"volume_scale": 2}})
    entry = out["endpoints"]["local-cheap"]
    for arm in ("current", "proposed"):
        c = entry[arm]["limits"]["max_concurrency"]
        o = entry[arm]["limits"]["output_tokens_per_minute"]
        print(f"step {arm}: concurrency peak {c['peak']:.4f} mean {c['mean']:.4f} "
              f"over {c['buckets_over']}/{out['window']['active_buckets']} "
              f"requests_over {c['requests_over_share']:.4f} | "
              f"output peak {o['peak']:.4f} mean {o['mean']:.4f}")


def poisson_tail(mean: float, above: int) -> float:
    """P(N > above) for N ~ Poisson(mean)."""
    return 1.0 - sum(math.exp(-mean) * mean ** k / math.factorial(k) for k in range(above + 1))


def poisson() -> None:
    lam, service_s, hours, limit = 0.5, 4.0, 2, 2.4          # arrivals/s, s, h, concurrent
    rng = random.Random(20261007)
    rows, t, i = [], 0.0, 0
    while True:
        t += rng.expovariate(lam)
        if t >= hours * 3600:

        rows.append(row(i, T0 + timedelta(milliseconds=round(t * 1000)), service_s * 1000))
        i += 1
    out = block(rows, {"max_concurrency": limit})
    stated = out["endpoints"]["local-cheap"]["current"]["limits"]["max_concurrency"]
    buckets = out["window"]["active_buckets"]
    # A bucket is over when N x S / 60 > limit, i.e. N > limit x 60 / S.
    threshold = math.floor(limit * 60 / service_s)
    expected_share = poisson_tail(lam * 60, threshold)
    realised = len(rows) / (hours * 3600)

    print(f"poisson: mean offered concurrency {stated['mean'] * limit:.4f} "
          f"(theory lambda x S = {lam * service_s:.4f}; "
          f"from the realised rate {realised * service_s:.4f})")
    print(f"poisson: buckets over {stated['buckets_over']}/{buckets} = "
          f"{stated['buckets_over_share']:.4f} (Poisson tail P(N > {threshold}) = "
          f"{expected_share:.4f}, +/- {2 * math.sqrt(expected_share * (1 - expected_share) / buckets):.4f} at 2 sd)")
    print(f"poisson: peak {stated['peak']:.4f} at {stated['peak_bucket']}")

## Open risks

- **A utilisation can be mistaken for a measurement.** It is demand divided by a number somebody typed. The caveat is printed with every section and pinned by a test, but "230% of capacity" quoted without the limit and where it came from has lost the more important half.
- **Whether utilisation so defined tracks real endpoint behaviour is unmeasured.** A serving engine with continuous batching does not degrade at "100% of `max_concurrency`" the way a thread pool does. `arxiv.md` E10b is the experiment; until it is run the figure is a ratio, not a prediction.
- **One latency per endpoint.** Offered concurrency is the request rate times a constant. A row moved to another endpoint gets that endpoint's median, and an endpoint with no observed row gets its tier default (flagged). Per-request service time is B66 item 3.
- **Arrival is estimated** as `ts` minus the recorded latency. A failure row's latency includes gate time, and a row with no usable latency is placed at its write time.
- **`volume_scale` is a multiplier.** It can make 24 rows read as a production load. The minimum-bucket rule counts buckets, not scaled requests, and ten buckets is a floor, not evidence.
- **The mean is over buckets that hold traffic.** That is the right denominator for a sparse test export and a slightly flattering one for a production export with a quiet night: quiet buckets with no request at all are left out.
- **Peak depends on the bucket.** 60 s is a convention; the same rows give a lower peak at 300 s and a higher one at 10 s. The block records the bucket, and two runs with different buckets have different ids, but nothing warns that a peak is bucket-relative beyond the documentation.
- **No range.** A reader used to P3c-3's brackets will find none here and a sentence saying why. A block bootstrap is B66 item 2.
- **Failover load is absent.** First-decision replay puts each request on one endpoint. A deployment that fails over often carries more load than this shows.
- **The capacity file is hand-written and keyed by slug.** It goes stale when endpoints change; a slug that no longer exists is a load error, but a limit that is simply out of date is not detectable. A declaration on the onboarded endpoint is B66 item 1.
- **The roadmap had promised a predicted-rejection figure.** This plan deliberately does not build one (spec §9.2). The owner may still want it; that is a decision about asserting an endpoint behaviour RouteForge cannot see.
- **The comparison table is one column wider**, on top of P3c-3's brackets.
